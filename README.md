# fusion_py
## can_to_message.py
This file contains the functions that take a given CAN message and translates into our Track ROS message. It contains essentially multiple copies of the same function with different dictionary accesses due to the fact that the signals in each CAN message varry slightly between each other and which generation is used.

## CanGPSReader.py
This is a ROS node that reads off Socket Can and translate the GPS messages received on Global B Can 5, and publishes them in the format of our GPS ROS message.

### Configure PC and Socket CAN
As currently configured in the ConnAu Hummer you will need to configure the Linux PC and Socket CAN with the following command once per power on of the PC. If you have done this step for [CanTrackReader](#cantrackreaderpy) you do not need to do it again.

```
sudo modprobe peak_usb
sudo modprobe peak_pci
```

The following commands may change slightly if the Hummer setup is modified but the general commands should still be correct. Such as if you change which USB slot the PCAN device is plugged into or which CAN slot on the PCAN device CAN 5 is connected to. To update you should just have to change 'can0' to 'canX' where X is a different number. As a note you will need to update the code to reflect this change as well.

```
sudo ip link set can0 up type can bitrate 500000
```

If everything is configured correctly the CAN Light for the CAN connection on the device should be blinking green after running the command. If it is blinking Red, something has been configured incorrectly. Please ensure you have the right CAN network attached to the connection you are trying to configure, as GM CAN and GM CAN FD have different settings. If not the following command will turn off the connection and allow you to try to re-setup the connection with new parameters
```
sudo ip link set can0 down
```

### Run Node
To run this node use the following command, make sure you have sourced the project

```
ros2 run fusion_py CANGPSReader
```
## CanTrackReader.py
This is a ROS node that reads off Socket Can and translate the Sensor Data messages received on Global B Can 8, and publishes them in the format of our Track ROS message.

### Configure PC and Socket CAN
As currently configured in the ConnAu Hummer you will need to configure the Linux PC and Socket CAN with the following command once per power on of the PC. You do need to run both sets. If you have done this step for [CanGPSReader](#cangpsreaderpy) you do not need to do it again.

```
sudo modprobe peak_usb
sudo modprobe peak_pci
```

The following commands may change slightly if the Hummer setup is modified but the general commands should still be correct. Such as if you change which USB slot the PCAN device is plugged into or which CAN slot on the **PCAN Pro**, which is black and has two can slots, device CAN 8 is connected to. To update you should just have to change 'can0' to 'canX' where X is a different number. As a note you will need to update the code to reflect this change as well.
```
sudo ip link set can1 up type can bitrate 500000 sample-point 0.8 dbitrate 2000000 dsample-point 0.8 fd on
```

If everything is configured correctly the CAN Light for the CAN connection on the device should be blinking green after running the command. If it is blinking Red, something has been configured incorrectly. Please ensure you have the right CAN network attached to the connection you are trying to configure, as GM CAN and GM CAN FD have different settings. If not the following command will turn off the connection and allow you to try to re-setup the connection with new parameters
```
sudo ip link set can1 down
```

### Run Node
To run this node use the following command, make sure you have sourced the project
```
ros2 run fusion_py CANTrackReader
```

## ComparisonVisualizerv2.py
NOTE: ComparisonVisualizer.py is left as legacy, and should no longer be used. It may be deleted in the future.

This ROS Node takes a file generated by VehicleLoggingScripts/TrackVsGroundTruthv2.py and will take the tracks and ground truth data and publish them to RVIZ and our Fusion node. This allows us to visualize the performance of the sensors and fusion algorithm.

```
ros2 run fusion_py ComparisonVisualizerv2 Comparison.csv
```

## data_publisher.py

This ROS Node takes a log file generated by VehicleLoggingScripts/FileTransformer.py and publish the sensor and gps data to the ROS Environment. It takes two parameters, one is the file to read, and the second is which MY to use the default is MY24, the other option is MY22.

```
ros2 run fusion_py data_publisher data-Transformed.txt MY24
```

## SerialGPS.py
This ROS Node reads GPS data from a Serial Port provided by a Ublox.

### Configure Linux PC and Serial USB

```
Sudo stty -F /dev/ttyUSB0 115200 
```
Then you should be able to run the script, if you get a permission error for /dev/ttyUSB0 

```
Sudo chmod 777 /dev/ttyUSB0
```

There is also a non 0 chance that it is not USB0, so you may need to validate which USB# it is, you should get errors if you run the script and it isn't usb0

## VehicleCommander.py
This ROS node acts as a ROS Message to CAN Message converter due to the CAN interfacing being more convient in python. It will receive VehicleControl ROS message and convert it to a CAN Signal which will be sent via SocketCAN and PCAN Device to the MicroAutobox.
